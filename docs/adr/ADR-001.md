# ADR-001: Firestore Note Serialization, Real-Time Streams, and Security Rules

**Date:** 2026-11-11  **Author:** serhat yavuz  **Milestone:** Lab 5
**Tool and model used:** OpenCode + Gemini 4 Argon (Medium)

## Context
In Lab 5 (Study Notes), we needed to integrate Firebase Authentication, Cloud Firestore, and Firebase Cloud Messaging (FCM) into a Flutter app while keeping unit and widget tests isolated using in-memory fakes (`FakeFirebaseFirestore` and `MockFirebaseAuth`). Specifically, we needed to serialize `Note` documents without duplicating the document ID inside the document payload, stream real-time user-scoped notes ordered by server timestamp, map `FirebaseAuthException` error codes to user-friendly messages, and enforce per-user access and title length constraints in `firestore.rules`.

## Prompt
```
How should we implement Note.fromFirestore/toFirestore, NotesRepository (watchNotes, addNote, deleteNote) at users/{uid}/notes/{noteId}, and the corresponding Firestore security rules so that only the authenticated owner can read/delete their notes and only valid 1-100 character titles can be created or updated?
```

## Result
We implemented (commits `d5e3be6`, `377ac13`, `89c08a0`):
1. `Note.fromFirestore` and `Note.toFirestore`: validates that `title` and `body` are `String`s (throwing `FormatException` otherwise), converts nullable `Timestamp` `createdAt` to `DateTime?`, and writes `'createdAt': FieldValue.serverTimestamp()` without storing `id` as a document field.
2. `AuthRepository`: trims the email on `signIn` and `signUp`, catches `FirebaseAuthException`, and converts it into `AuthFailure(messageFor(e.code))` using a Dart switch expression.
3. `NotesRepository` & `NotesScreen`: queries `users/{uid}/notes` with `.orderBy('createdAt', descending: true).snapshots()`, trims `title` and `body` in `addNote` while throwing `ArgumentError` if the trimmed title is empty or exceeds 100 characters, and caches the stream in `_NotesScreenState` so rebuilds do not recreate the Firestore listener.
4. `firestore.rules`: restricts `read, delete` to `request.auth != null && request.auth.uid == uid`, and additionally validates `request.resource.data.title is string && request.resource.data.title.size() >= 1 && request.resource.data.title.size() <= 100` on `create, update`.

```dart
// Key diff in lib/data/notes_repository.dart & firestore.rules:
Stream<List<Note>> watchNotes(String uid) {
  return _notes(uid)
      .orderBy('createdAt', descending: true)
      .snapshots()
      .map((snapshot) => snapshot.docs
          .map((doc) => Note.fromFirestore(doc.id, doc.data()))
          .toList());
}
```

## Rejected suggestion(s) — at least one
1. **Storing `id` inside the Firestore document map and using `DateTime.now()` on the client:** An initial suggestion included `'id': id` and `'createdAt': Timestamp.fromDate(DateTime.now())` inside `toFirestore()`. We rejected this because the document ID is already provided by the Firestore document reference (`doc.id`), and client clocks can be skewed; using `FieldValue.serverTimestamp()` ensures consistent server-side ordering and is explicitly required by the test suite.
2. **Calling `watchNotes(widget.uid)` directly inside `NotesScreen.build()`:** Calling `watchNotes` inline inside `StreamBuilder(stream: context.read<NotesRepository>().watchNotes(widget.uid), ...)` was rejected because every widget rebuild would create a new Firestore snapshot listener and reset the stream state. Instead, we kept the `late final Stream<List<Note>> _notes` field initialized once in `State`.

## What I learned
Injecting `FirebaseAuth` and `FirebaseFirestore` instances through constructors (`AuthRepository(this._auth)` and `NotesRepository(this._db)`) allows the entire authentication and Firestore data layer to be tested deterministically in memory using `MockFirebaseAuth` and `FakeFirebaseFirestore` without requiring a live Firebase connection in CI.
